# 프로젝트 지시서: 산불 확산 예측 및 등산객 대피 안내 시스템

너는 이 프로젝트의 개발 파트너야. 우리는 대학교 1학년 2인 팀이고, "C언어기초" 과목의 팀 프로젝트로 이 프로그램을 만든다.
코드를 작성하기 전에 먼저 이 문서를 끝까지 읽고, 아래 "진행 방식"을 반드시 지켜줘.

---

## 1. 프로젝트 개요

- **산업 분야**: 산림 재난 관리 (산불 확산 예측, 주민·등산객 대피, 진화 자원 배치)
- **한 줄 소개**: 실제 기상 데이터를 받아 산불이 어떻게 번질지 예측하고, 산에 있는 등산객에게 가장 안전한 대피 경로를 안내하며, 방화선·진화 헬기를 어디에 배치하면 피해가 가장 줄어드는지 계산하는 시스템
- **목적 (3개 이상, 과제 Type 2 조건)**
  1. 산불 확산 예측: 연료(숲 종류), 경사, 바람, 습도를 반영한 시간대별 확산 시뮬레이션
  2. 등산객 대피 경로: 불이 도착하는 시간을 고려해 등산로 위에서 가장 안전한 대피 경로 탐색 + 경보 단계 판정
  3. 진화 전략: 방화선·진화 헬기 배치 위치 최적화, 배치 전후 피해 비교
  4. (보조) 몬테카를로 반복 실험으로 확산 결과의 확률 지도 생성

## 2. 과제 조건 (반드시 지킬 것)

- **주언어는 C**. 핵심 계산은 전부 C로 작성한다. Python은 화면(GUI)과 데이터 다운로드·변환만 담당한다.
- **목표 분량: 총 약 12,000줄** (C 약 8,000줄, Python 약 4,000줄). 단, 줄 수를 늘리기 위한 의미 없는 코드는 넣지 마. 기능을 제대로 만들면 자연스럽게 도달하는 구조로 설계해줘.
- C 코드는 **Windows + Visual Studio 2022의 MSVC 컴파일러**에서 경고 없이 빌드되어야 한다.
  - 표준 C(C11)와 Windows 기본 라이브러리만 사용. 외부 C 라이브러리 금지.
  - `fopen` 등 보안 경고는 `_CRT_SECURE_NO_WARNINGS`로 처리.
  - `build.bat`(Developer Command Prompt에서 `cl`로 빌드)과, Visual Studio 빈 프로젝트에 파일을 추가해 빌드하는 방법 둘 다 README에 적어줘.
- GitHub 등 외부 코드를 통째로 복사하지 말 것. 참고한 알고리즘이 있으면 출처를 주석과 문서에 남겨줘.
- 우리가 발표 영상에서 한 사람당 4분 이상 코드를 설명해야 한다. **1학년이 읽고 이해할 수 있는 코드**로 써줘.
  - 함수는 짧게, 이름은 의미가 드러나게, 주석은 한국어로.
  - 복잡한 포인터 트릭, 매크로 남용, 지나친 최적화는 피하기.

## 3. 전체 구조

```
wildfire_project/
├── c_core/              # C 계산 엔진 (wildfire.exe)
│   ├── include/         # 헤더 (구조체 정의)
│   ├── src/             # 소스 파일 (기능별로 분리)
│   └── build.bat
├── gui/                 # Python GUI
│   ├── main.py
│   ├── views/           # 화면별 파일
│   └── services/        # C 실행, 데이터 로딩, 기상 API
├── data/
│   ├── maps/            # 지형·연료 격자 파일
│   ├── trails/          # 등산로 그래프 파일
│   ├── weather/         # 기상 데이터 (API 결과 또는 샘플)
│   └── scenarios/       # 시나리오 설정 파일
├── output/              # C가 저장하는 결과 (JSON/CSV)
├── docs/                # 설계 문서, 프롬프트 기록
└── README.md
```

**C와 Python의 연결 방식**
- Python GUI가 `subprocess`로 `wildfire.exe`를 실행한다. 인자로 시나리오 설정 파일 경로를 넘긴다.
- C는 진행 상황을 표준출력(stdout)에 한 줄씩 출력하고, Python은 이를 읽어 화면 상단에 표시한다.
- C는 결과를 `output/` 폴더에 시간 단계별로 저장하고(JSON 또는 CSV), Python이 읽어서 애니메이션으로 재생한다.

## 4. C 계산 엔진 상세 (약 8,000줄)

### 4-1. 데이터 구조 (헤더에 정의)
- `Cell`: 고도, 경사, 경사 방향, 연료 종류, 연료 수분, 상태(정상/연소 중/전소/방화선/물/바위), 불이 도착한 시각
- `FuelModel`: 연료 종류별 확산 계산 파라미터
- `Weather`: 시각별 기온, 상대습도, 풍속, 풍향
- `TrailNode`, `TrailEdge`: 등산로 그래프 (교차점, 대피소, 주차장 등 노드 / 거리·경사가 있는 간선)
- `Hiker`: 현재 위치, 이동 속도, 대피 상태
- `Scenario`: 위 모든 설정을 묶은 구조체

### 4-2. 모듈 구성 (예상 분량)
1. **설정·지도 입출력** (~1,200줄): 시나리오 파일, 지형 격자, 연료 격자, 등산로 그래프 읽기. 입력 오류 검사와 친절한 오류 메시지.
2. **기상·연료 수분** (~800줄): 시각별 기상 값을 보간하고, 기온·습도로 연료 수분을 계산.
3. **확산 엔진** (~1,600줄):
   - Rothermel 지표화 확산 모델을 단순화해서 사용: 확산 속도 = 기본 속도 × (1 + 바람 계수 + 경사 계수)
   - 격자 기반으로 8방향 확산, 각 셀에 "불이 도착한 시각"을 기록
   - 확률 요소(비화 등)는 시드 고정이 가능한 난수로 처리해 결과 재현 가능하게
   - 모델의 계수와 단순화한 부분은 주석과 `docs/model.md`에 정리
4. **몬테카를로 실험** (~600줄): 같은 조건으로 N회 반복해 셀별 연소 확률 지도와 평균 피해 면적 계산.
5. **대피 경로** (~1,500줄):
   - 등산로 그래프 위에서 대피소·주차장까지 경로 탐색 (다익스트라 또는 A*, 우선순위 큐 직접 구현)
   - 시간에 따라 불이 다가오므로, "내가 그 지점을 지나는 시각"과 "불이 그 지점에 도착하는 시각"을 비교해 안전 여유가 가장 큰 경로 선택
   - 등산객 위치별 경보 단계 판정 (예: 화선 도착까지 남은 시간 기준으로 주의 / 대피 준비 / 즉시 대피). 기준 시간은 설정 파일에서 바꿀 수 있게.
6. **진화 전략** (~1,000줄):
   - 방화선 K칸 또는 진화 헬기 M대를 어디에 배치할지 탐욕법으로 탐색
   - 배치 전후 피해 면적, 위험에 처한 등산객 수 비교
7. **결과 출력·로그** (~800줄): 시간 단계별 격자 상태, 대피 경로, 통계를 JSON/CSV로 저장. 진행 로그 출력.
8. **공통 유틸** (~500줄): 동적 배열, 우선순위 큐, 난수, 수학 함수, 메모리 해제.

### 4-3. 꼭 들어가야 할 것
- 구조체, 포인터, 동적 할당(`malloc`/`free`), 파일 입출력, 2차원 배열이 자연스럽게 쓰이도록
- 발표자료용 **주요 함수 5개 이상**이 명확히 드러나도록 (예: `load_scenario`, `compute_spread_rate`, `simulate_fire_step`, `find_safest_route`, `optimize_firebreak`)
- 메모리 누수 없이 종료

## 5. Python GUI 상세 (약 4,000줄)

- 라이브러리: **PySide6 + PyQtGraph** (실시간 격자 애니메이션이 빨라야 함). 다크 테마로 깔끔하게.
- **화면 구성**
  1. 메인 지도: 위에서 내려다본 산 지형(등고선 또는 음영) 위에 연료 색, 불 번짐 애니메이션, 등산로, 등산객 위치, 대피 경로 표시
  2. 재생 컨트롤: Play/Pause, 타임라인 슬라이더, 재생 속도
  3. 시나리오 설정 패널: 발화 지점(지도 클릭), 계절 프리셋, 풍향·풍속·습도 슬라이더, 실제 기상 데이터 불러오기 버튼
  4. 대피 화면: 등산객별 경보 단계(색상 배지), 추천 경로, 남은 안전 시간
  5. 진화 전략 화면: 방화선·헬기 배치 전후 비교를 나란히 표시
  6. 통계·그래프: 시간별 피해 면적, 확산 속도, 몬테카를로 연소 확률 지도
  7. 결과 리포트: 시뮬레이션 요약을 텍스트·이미지로 저장
- C 프로그램 실행 상태(stdout)를 화면 상단에 실시간 표시

## 6. 데이터

- **기상**: 공공데이터포털의 기상청 단기예보 API 또는 국립산림과학원 측정데이터 API를 Python으로 받아 `data/weather/`에 C가 읽기 쉬운 텍스트로 저장. API 키는 코드에 직접 쓰지 말고 설정 파일로 분리. 인터넷이 없을 때를 위한 **샘플 기상 파일**도 함께 제공.
- **지형·연료**: 처음에는 가상의 산을 만드는 생성기(능선·계곡이 있는 지형 + 침엽수/활엽수/풀 구역)로 시작. 나중에 실제 지형 데이터를 Python으로 변환해 같은 형식의 격자 파일로 넣을 수 있게 파일 형식을 설계.
- **등산로**: 처음에는 가상 등산로 그래프 파일로 시작. 실제 등산로 데이터로 교체 가능하게.
- 계절별·지역별 수치는 코드에 숨기지 말고 `data/scenarios/`의 설정 파일로 빼고, 어떤 값이 실제 근거가 있고 어떤 값이 가정인지 표시해줘.

## 7. 진행 방식 (중요)

1. **먼저 코드를 쓰지 말고** `docs/PROJECT_SPECIFICATION.md`를 작성해줘: 전체 구조, 파일 목록과 각 파일의 역할, 구조체 정의, 주요 함수 목록, 데이터 파일 형식, 개발 단계 계획, 파일별 예상 줄 수. 작성 후 우리에게 확인을 받아.
2. 승인 후 **단계별로** 개발한다. 각 단계가 끝날 때마다 빌드·실행 방법을 알려주고, 우리가 실행해서 확인한 뒤 다음 단계로 넘어간다.
   - 1단계: C 데이터 구조 + 지도·설정 읽기 + 콘솔에 지도 출력
   - 2단계: 확산 엔진 + 결과 파일 저장
   - 3단계: Python GUI 기본 화면 + 결과 재생 애니메이션
   - 4단계: 대피 경로 + 경보
   - 5단계: 진화 전략 최적화 + 비교 화면
   - 6단계: 기상 API 연동, 몬테카를로, 통계·리포트
   - 7단계: 다듬기, 오류 처리, 문서 정리
3. 각 단계가 끝나면 `docs/CHANGELOG.md`에 무엇을 만들었는지, `docs/LINE_COUNT.md`에 언어별·파일별 줄 수를 갱신해줘.
4. 중요한 함수를 만들 때는 그 함수가 하는 일을 2~3줄로 설명해줘. 발표에서 우리가 직접 설명해야 한다.
5. 결정이 필요한 부분(라이브러리 선택, 단순화 정도 등)은 마음대로 정하지 말고 선택지와 장단점을 알려준 뒤 물어봐줘.
