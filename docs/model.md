# 계산 모델 설명 (model.md)

이 문서는 C 엔진이 사용하는 계산 모델과, 원래 모델에서 **무엇을 단순화했는지**, 각 수치가 **근거가 있는 값인지 가정인지**를 정리한다.

- **[근거]**: 논문·공식 자료에 있는 식이나 값
- **[형태 근거]**: 식의 모양은 논문을 따랐지만 계수는 팀이 정함
- **[가정]**: 팀이 그럴듯하게 정한 값. 실제 자료로 보정이 필요함

> 6단계 기준 (확산·수분·비화·대피·진화 전략·몬테카를로·실제 기상).

## 2. 지형: 경사와 경사 방향 — Horn(1981) [근거]

주변 3×3 셀 고도 `a b c / d e f / g h i` (위쪽 행 = 북쪽)로

```
dz_east  = ((c + 2f + i) − (a + 2d + g)) / (8 × 칸크기)
dz_south = ((g + 2h + i) − (a + 2b + c)) / (8 × 칸크기)
경사      = atan( √(dz_east² + dz_south²) )
경사 방향 = atan2(−dz_east, dz_south)   (내리막이 향하는 방위, 북 = 0°)
```

경사 방향은 연료 수분 보정(남향 사면)에 쓰고, 확산 계산의 경사 효과는 **두 셀 사이의 실제 고도 차이**로 계산한다(6장).

## 3. 기상 보간

- 기상 기록(보통 1시간 간격) 사이의 값은 **선형 보간**: `값 = 앞 + (뒤 − 앞) × 비율`
- 풍향은 **원형 보간**: 350°와 10°의 중간은 0°가 되도록 차이를 −180° ~ 180°로 바꾼 뒤 보간
- 기록 범위 밖은 가장 가까운 끝 기록 값을 쓰고 경고를 출력

## 5. 연료 수분

### 5-1. 평형 수분 EMC — Simard(1968) [근거]

기온 T(°F), 상대습도 H(%)로 다음과 같이 계산한다.

| 습도 구간 | EMC (%) |
|---|---|
| H < 10 | 0.03229 + 0.281073 H − 0.000578 H T |
| 10 ≤ H < 50 | 2.22749 + 0.160107 H − 0.01478 T |
| H ≥ 50 | 21.0606 + 0.005565 H² − 0.00035 H T − 0.483199 H |

예) 20 °C, 습도 20% → 약 4.4% / 10 °C, 습도 55% → 약 10.4%

### 5-2. 시간 지연 [근거: 연료 시간지연(timelag) 개념]

```
M(다음) = M + (EMC − M) × (1 − e^(−dt/τ)),   τ = 60분 (1시간 지연 연료)
```

연료 수분은 공기 변화를 바로 따라가지 않고 천천히 따라간다. 1-hour fuel은 지름 6 mm 미만의 가는 연료(낙엽, 잔가지)를 말한다.

### 5-3. 보정 [가정]

| 보정 | 내용 |
|---|---|
| 남향 사면 | 경사 5° 이상이고 경사 방향 135°~225°인 셀은 수분을 `south_slope_drying_pct`(기본 2%p)만큼 낮춘다 |
| 계절 배율 | 확산 계산에는 `셀 수분 × live_moisture_factor`를 쓴다. 살아 있는 잎·풀의 수분을 대신하는 단순화로, 봄은 1.0이다 |
| 초기값 | `initial_dead_moisture_pct` = 8% (봄철 건조기) |

## 6. 확산 속도 — Rothermel(1972) 단순화

```
R = R0 × η_M × (1 + φw + φs)            (m/분)
```

| 요소 | 식 | 구분 |
|---|---|---|
| η_M 수분 감쇠 | r = 수분/소화수분 (0~1), `η = 1 − 2.59r + 5.11r² − 3.52r³` | [근거] Rothermel(1972) |
| φw 바람 (순풍) | 확산 방향 바람 성분 `U·cosθ > 0` 이면 `kw × (U·cosθ)^bw` (U: m/s) | [형태 근거] |
| φw 바람 (맞바람) | `−0.5 × (1 − e^(U·cosθ / 3))` (최대 50% 감속) | [가정] |
| φs 오르막 | `ks × tan²(경사각)`, tan = (이웃 고도 − 현재 고도) / 수평 거리 | [형태 근거] |
| φs 내리막 | `−0.5 × min(1, ks × tan²)` (최대 50% 감속) | [가정] |
| 하한 | `1 + φw + φs ≥ 0.05` | [가정] |

- θ는 확산 방향과 "바람이 불어 가는 방향(풍향 + 180°)" 사이의 각이다.
- 연료와 수분은 **불이 들어갈 이웃 셀**의 값을 쓴다.

### 원래 Rothermel 모델과 다른 점

1. 원래 모델은 연료 입자 표면적, 밀도, 열량, 광물질 함량 등 10여 개 값으로 R0와 계수를 계산한다. 여기서는 연료별로 R0, kw, bw, ks 네 값만 표로 주었다.
2. 원래 모델의 풍속 단위는 중간 화염 높이 풍속(ft/min)이지만, 여기서는 기상 자료의 풍속(m/s)을 그대로 쓰고 계수로 흡수했다.
3. 맞바람·내리막 감속은 원래 모델에 없는 항목으로, 가정으로 추가했다.
4. 수관화(나무 꼭대기로 번지는 불)는 따로 모델링하지 않았다.

### 계산 예 (침엽수, 연료 수분 5%, 순풍 8 m/s, 평지)

```
η_M = 1 − 2.59(0.2) + 5.11(0.2)² − 3.52(0.2)³ ≈ 0.66   (r = 5/25 = 0.2)
φw  = 0.35 × 8^1.3 ≈ 0.35 × 14.9 ≈ 5.2,   φs = 0
R   = 1.2 × 0.66 × (1 + 5.2) ≈ 4.9 m/분 ≈ 0.29 km/h
```

## 7. 격자 확산 방식 (spread_sim.c)

**누적 거리 셀룰러 오토마타**

1. 매 단계(dt = 1분) 화선 셀은 8방향으로 `R × dt`만큼 "진행 거리"(`progress[방향]`)를 늘린다.
2. 진행 거리가 이웃까지의 거리(30 m 또는 42.4 m) 이상이 되면 이웃에 불이 붙는다.
   - 도착 시각 = `t + dt − (넘친 거리 / R)` → 분 단위 소수까지 기록한다.
3. 한 단계 안에서 여러 셀이 같은 이웃에 도착하면 **가장 이른 도착**을 남긴다. 그 출발 셀은 `parent_index`에 기록한다(5단계 진화 전략에서 "점화 트리"로 사용).
4. 모든 셀이 같은 시점의 상태를 보고 계산하도록, 점화는 단계 끝에 한꺼번에 한다.

**두 목록을 나눈 이유**

| 목록 | 의미 | 빠지는 시점 |
|---|---|---|
| 화선 (front) | 이웃으로 불을 밀어내는 중 | 탈 수 있는 이웃이 더 없을 때 |
| 연소 (burning) | 불꽃이 있음 (화면의 "연소 중", 비화의 출발점) | 연료별 연소 시간이 지나 전소될 때 |

불꽃이 꺼질 때 확산까지 멈추게 하면, 연소 시간이 3분인 초지에서 불이 30 m를 가기 전에 꺼져 버린다. 실제로는 화선이 계속 이동하므로 두 개념을 분리했다.

**대각선 차단 규칙**

대각선으로 번질 때 양옆 두 칸이 모두 장벽(물·바위·도로·방화선)이면 막는다. 한 칸 두께의 대각선 방화선을 불이 모서리 틈으로 빠져나가는 것을 막기 위한 규칙이다.

## 8. 비화 (spotting.c) — 모두 [가정]

| 단계 | 식 |
|---|---|
| 발생 확률 (연소 셀 1개, 1분당) | `p = spot_base_prob × spot_factor × (U/10)²`, U < 2 m/s 이면 0 |
| 거리 | 지수 분포, 평균 = `spot_mean_dist_m × U / 5` |
| 방향 | 바람이 불어 가는 방향 ± 정규 분포(표준편차 15°) |
| 착화 | 떨어진 셀이 탈 수 있고, 난수 < 그 셀의 η_M 이면 점화 |

- 1.5칸보다 가까운 비화는 일반 확산과 같으므로 무시한다.
- 난수는 **xorshift32**(Marsaglia 2003)이고 시드를 고정할 수 있어, 같은 시드면 결과가 같다.
- **사건별 난수 (공통 난수, 5단계에서 변경)**: 난수 하나를 모든 셀이 차례로 꺼내 쓰면, 방화선 때문에 셀 하나만 덜 타도 그 뒤의 모든 비화가 바뀐다. 그러면 전략 비교에서 "운"의 차이가 "효과"보다 커진다. 그래서 (시드, 셀 번호, 시각)을 섞어 그 사건만의 난수를 만든다(`rng_seed_for_event`). 같은 셀이 같은 시각에 타면 어느 전략에서나 같은 비화가 생긴다.

## 10. 대피 안내 (evac_route.c, evac_alert.c, hiker.c)

### 10-1. 위험 지도

불이 지나간 셀마다 반경 R 안의 모든 셀에 "이 시각에 근처까지 불이 온다"를 기록한다(가장 이른 시각이 남음). 지도는 두 개를 만든다.

| 지도 | 반경 | 용도 |
|---|---|---|
| 경보용 | `check_radius_m` = 500 m [가정] | 경보 단계 판정, 출발 시각 |
| 경로용 | `danger_radius_m` = 60 m [가정] | 경로의 안전 여유 (화염의 복사열이 닿는 거리를 단순화) |

### 10-2. 경보 단계 [기준 시간은 모두 가정, 설정 파일에서 변경 가능]

남은 시간 = (현재 위치 주변 500 m 안에 불이 오는 시각) − 현재 시각

| 단계 | 조건 (기본값) |
|---|---|
| 정상 | 남은 시간 ≥ 120분, 또는 불이 오지 않음 |
| 주의 | 남은 시간 < 120분 (`caution_min`) |
| 대피 준비 | 남은 시간 < 60분 (`prepare_min`) → **이때 대피 출발** |
| 즉시 대피 | 남은 시간 < 30분 (`immediate_min`) |
| 고립 | 출발할 때 이미 안전한 경로가 없음(최소 여유 < 0), 또는 걷다가 불에 막힘 |

**출발 시각** = max(발화 + `notify_delay_min`, 시작 위치가 "대피 준비"가 되는 시각)

### 10-3. 보행 속도 — Tobler(1993) [근거]

```
v = 평지 속도 × e^(−3.5 × |기울기 + 0.05|) / e^(−3.5 × 0.05)
```

원래 식은 `v = 6 e^(−3.5|s + 0.05|)` km/h이다. 팀마다 평지 속도가 다르므로 비율만 사용한다. 최저 속도는 0.3 km/h로 제한했다 [가정].

| 기울기 | 평지 3.5 km/h인 사람의 속도 |
|---|---|
| −5% (완만한 내리막) | 4.1 km/h (가장 빠름) |
| 0% | 3.5 km/h |
| +20% (오르막) | 1.6 km/h |
| −30% (급한 내리막) | 1.7 km/h |

### 10-4. 가장 안전한 경로 — 다익스트라 변형

- 지점의 안전 여유 = 위험 시각(경로용 지도) − 내가 지나는 시각
- 경로의 안전 여유 = 경로 위 최솟값
- 노드마다 (최소 여유, 도착 시각)을 기록한다. 직접 만든 이진 힙 우선순위 큐로 "여유가 크고, 같으면 빨리 도착하는" 노드부터 확정한다.
- 여유가 `safe_margin_min`(30분) 이상이면 모두 같은 값으로 본다. 그래서 충분히 안전한 경로들 중에서는 가장 빠른 길을 고른다.
- **목적지**: 주차장은 항상 목적지다. 대피소는 위험 반경 안에 불이 끝까지 오지 않을 때만 목적지로 본다 [가정].
- **한계**: 도착 시각이 경로에 따라 달라지기 때문에(시간 의존 그래프) 이 방법이 수학적 최적을 항상 보장하지는 않는다. 가상 등산로(노드 11개)에서는 결과를 눈으로 확인했다.

### 10-5. 이동과 고립

경로의 셀을 하나씩 걸으며 시각을 계산한다. 다음 셀에 이미 불이 도착해 있으면 그 앞에서 멈추고 **고립**으로 본다.

**위험 등산객** = 고립된 팀, 또는 경로의 최소 여유가 `immediate_min`(30분)보다 작은 팀. 5단계 진화 전략에서 비교 지표로 쓴다.

### 10-6. 실험 예 (`spring_danger_valley.ini`)

계곡 아래에서 발화했고, 남서풍 11 m/s, 습도 14%이며 발견·신고가 늦어진 경우이다(9 km 지도, 10시간). 같은 날씨에서 신고 지연만 바꿔 보았다(시드 1~5, 42의 6회).

| 신고 지연 `notify_delay_min` | 고립 팀 (6회 중) |
|---|---|
| 60분 | 모두 0팀 (여유 30분 미만인 "위험" 팀만 0~2팀) |
| 80분, 100분 | 모두 0팀 (위험 팀 0~3팀) |
| 120분 | 2회에서 1팀 고립 |
| 140분 (시나리오 기본값) | 4회에서 1팀 고립 (시드 42: 계곡대피소의 가족 4명 고립, 위험 2팀 7명) |

- 신고 지연이 길면 `prepare_min`을 늘려도 결과가 같다. 모든 팀이 신고 시각이 되어야 출발할 수 있기 때문이다.
- 6 km 지도를 쓰던 4~6단계에는 신고 지연 100분에서 고립이 생겼다. 지도를 9 km로 키우면서 등산로도 1.5배 길어져 등산객에게 시간 여유가 생겼으므로, 시나리오 값을 140분으로 다시 정했다.
- → **경보 기준보다 조기 발견(감시)이 더 중요하다**는 것을 보여 준다.
- (4단계 처음 기록에서는 신고 지연 40분에서도 2팀이 고립됐다. 이는 비화 난수가 바꾸기 전 방식이었을 때 우연히 나온 결과였고, 5단계에서 시드를 여러 개 시험해 바로잡았다.)

## 11. 진화 전략 (suppression.c, suppression_eval.c)

### 11-1. 점화 트리와 하위 가치

- 셀마다 "누구에게서 불을 받았는지"(`parent_index`)를 이으면, 발화 지점을 뿌리로 하는 나무가 된다.
- **하위 가치** = 그 셀과, 그 셀을 거쳐 불이 붙은 모든 셀의 가치 합이다. 셀 가치는 1이고 등산로 셀은 10이다 [가정].
- 계산 방법: 불이 늦게 도착한 셀부터 차례로 자기 값을 부모에게 더한다. 자식은 항상 부모보다 늦게 불이 붙으므로 한 번 훑으면 끝난다.
- 의미: "이 셀을 막으면 (불이 다른 길로 돌아가지 않는다면) 이만큼의 피해를 막는다"는 추정치이다.

### 11-2. 방화선 배치 — 탐욕법

| 단계 | 내용 |
|---|---|
| 1 | 현재 방화선을 반영해 시뮬레이션하고, 점화 트리로 하위 가치를 계산한다 |
| 2 | 후보 = 방화선 완성 시각(60분) 이후에 불이 도착하는 셀을 중심으로, 불이 들어온 방향에 수직인 5칸 조각 (셀 하나만 막으면 불이 옆으로 돌아가므로) |
| 3 | 조각 점수(하위 가치 합)가 높고 서로 떨어진 후보 3개를 실제로 시뮬레이션해, 피해 가치가 가장 작은 것을 고른다 |
| 4 | K칸(기본 60칸)을 다 쓰거나 더 이상 줄지 않을 때까지 반복한다 |

- 방화선은 시작부터 격자에 표시한다. 다만 "완성 시각 이후에 불이 오는 셀"만 고르므로, 완성 전에 불이 닿는 일은 없다.
- 대각선 차단 규칙(7장) 덕분에 대각선 모양의 조각도 불을 막는다. 비화는 방화선을 넘을 수 있다.
- 한계: 탐욕법은 지금 가장 좋아 보이는 것을 고르므로 전체 최적을 보장하지 않는다. 모든 조합을 시험하는 방법은 후보 수가 너무 많아 불가능하다.

**"방화선 + 헬기" 전략용 방화선 (헬기를 고려한 탐색)**

방화선 탐색을 두 번 한다.

| 계획 | 후보를 시험할 때 | 쓰이는 전략 |
|---|---|---|
| ① 헬기 없이 고른 방화선 | 헬기 없이 시뮬레이션 | "방화선" |
| ② 헬기를 고려한 방화선 | 헬기 살수를 함께 시뮬레이션 (헬기가 불을 늦추는 동안 막을 곳을 고름) | "방화선 + 헬기" |

- 탐욕법은 한 조각씩만 보므로, ②가 "조각 하나로는 효과가 없어" 일찍 멈출 수 있다.
- 그래서 ①과 ②를 **둘 다 헬기와 함께 시뮬레이션해 보고 피해가 작은 쪽**을 "방화선 + 헬기"에 쓴다(같으면 ②).
- 따라서 "방화선 + 헬기"는 헬기 없이 고른 방화선에 헬기를 더한 것보다 나빠지지 않는다.

### 11-3. 헬기 살수

| 항목 | 내용 |
|---|---|
| 첫 살수 | 발화 + 신고 지연 + 출동 간격 [가정] |
| 이후 | 출동 간격마다 M대가 살수 |
| 목표 | 화선의 셀 중 "아직 타지 않은 이웃들의 (1 + 하위 가치) 합"이 가장 큰 곳 (불이 가장 큰 피해를 향해 가는 곳). 앞 헬기와 2r+1칸 이상 떨어진 곳 |
| 효과 | 반경 r칸 안의 셀은 효과 시간(45분) 동안 불이 붙지 않고, 이미 탄 셀도 불을 밀어내지 못함 [가정] |

### 11-4. 비교 결과 예

같은 시드에 사건별 난수(9장)를 써서 비교했다. (9 km 지도, 10시간, 방화선 60칸, 헬기 3대)

| 시나리오 | 대응 없음 | 방화선 | 헬기 | 방화선 + 헬기 |
|---|---|---|---|---|
| 기본 (`spring_dry_base`) 피해 | 584.3 ha | 167.8 ha (−71.3%) | 292.9 ha (−49.9%) | **4.1 ha (−99.3%)** |
| 위험 (`spring_danger_valley`) 피해 | 2,783.7 ha | 2,570.3 ha (−7.7%) | 2,583.1 ha (−7.2%) | 2,369.2 ha (−14.9%) |
| 위험 사례 위험 등산객 | 2팀 7명 | 1팀 4명 | 1팀 4명 | 1팀 4명 |

- **기본 시나리오**: 방화선만으로 피해가 70% 넘게 준다.
  - 헬기를 고려해 고른 방화선(55칸)과 헬기를 함께 쓰면 99% 넘게 준다.
  - 첫 살수(40분)로 불이 늦춰진 사이에, 60분에 완성되는 방화선이 아직 작은 불(약 4 ha)을 둘러싸 초기에 가두기 때문이다.
  - 헬기를 고려하지 않고 고른 방화선에 헬기를 더했을 때는 66.8%였다 → **두 자원을 함께 계획해야 효과가 크다**.
- **위험 시나리오**: 10시간 동안 2,800 ha가 타는 큰 불이다.
  - 짧은 방화선 조각으로는 피해가 거의 줄지 않아, 탐색이 15칸(3조각)에서 멈춘다.
  - 헬기를 고려한 탐색은 효과 있는 조각을 하나도 찾지 못했다. 그래서 "방화선 + 헬기"에는 헬기 없이 고른 15칸을 쓴다(−14.9%).
  - 불은 388분에 지도 가장자리(9 km)에 닿으므로, 그 뒤의 면적은 실제보다 작게 나온다.
  - → 큰 불에서는 진화보다 대피가 먼저다.

## 12. 몬테카를로 반복 실험 (montecarlo.c)

| 항목 | 내용 |
|---|---|
| 반복 | 같은 시나리오를 N회(기본 100회) 실행 |
| 회차마다 바꾸는 것 | 비화 시드(기본 시드 + 1 + i)와 기상 오차. 오차는 풍속 + N(0, 1 m/s), 풍향 + N(0, 15°), 습도 + N(0, 5%)이며 [가정], 한 회차 안에서는 같은 오차를 유지한다(= "예보가 이만큼 빗나간 날") |
| 연소 확률 | 셀이 탄 회차 수 / N |
| 보수적 도착 시각 | 셀마다 가장 이른 10% 회차의 도착 시각. 셀마다 "가장 작은 k개(k = N×10%)"만 삽입 정렬로 유지한다(메모리 N×셀 → k×셀) |
| 면적 통계 | 평균, 표준편차, 최소, 10%·50%·90% 분위(가장 가까운 순위 방식), 최대 |
| 보수적 대피 | 격자의 도착 시각을 보수적 도착 시각으로 잠시 바꿔 대피를 다시 계산한다(`evacuation_mc.json`). "예보보다 불이 빨리 오는 경우"에 대비한 안내 |

### 예 (`spring_dry_base`, 100회)

- 피해 면적: 평균 526.3 ha, 표준편차 171.0
- 범위: 최소 208.3, 10% 289.8, 중앙값 503.5, 90% 764.2, 최대 913.1 ha
- 기준 시뮬레이션(584.3 ha)은 분포의 가운데쯤에 있지만, **같은 조건에서도 피해가 약 4.4배까지 달라질 수 있다**.
- 한 번의 시뮬레이션만으로 판단하면 위험하다는 것을 보여 준다.

## 14. 실제 산 (gui/services/mountain_builder.py, forest_import.py)

### 14-1. 지형
| 항목 | 내용 |
|---|---|
| 자료 | AWS Open Data Terrain Tiles (terrarium 형식, 확대 수준 13, 픽셀 약 15 m). 한국 지역은 주로 SRTM 30 m 기반 [근거] |

| 격자 | 정상(등산로 자료가 정상에서 떨어져 있으면 자료와 정상이 함께 들어가는 위치) 위도·경도를 가운데로 300 × 300칸, 30 m. 9 km 범위라 등장방형 근사(위도 1° = 지구 반경 × π/180) 사용 — 거리 오차 0.1% 미만 |
| 보간 | 칸 중심 위치에서 타일 픽셀 4개 양선형 보간 |
| 확인 | 정상 고도(지도/공식): 북한산 810/836, 설악산 1,700/1,708, 한라산 1,935/1,947 m, (확인할 때 강원 오대산 1,558/1,563, 경남 지리산 1,898/1,915). 30 m 평균이라 봉우리 끝이 조금 깎인다 |

### 14-2. 연료
- **임상도 반영 시**: 다각형을 격자에 칠하고(칸 중심이 다각형 안이면, 구멍은 짝홀 규칙으로 제외) 임종 코드를 연료로 바꾼다.
  침엽수림 → 침엽수, 활엽수림 → 활엽수, 혼효림 → 혼효림 [근거: 임상도 임종 구분]. 죽림 → 관목 [가정]. 고도 0 m(바다) → 물.
  무립목지/비산림(코드 0)은 세부 이름(비고·수종 칸)으로 나눈다: 제지·암석지 → 바위(타지 않음), 미립목지·묘지 → 초지, 관목덤불 → 관목 [가정].
  북한산의 제지(약 960 ha)는 경사 중앙값 26.5°(숲 16.8°), 고도 중앙값 354 m 로 높고 가파른 곳에 몰려 있어 대부분 화강암 암벽으로 보았다.
  받은 도엽 안인데 다각형이 없는 곳은 시가지·농경지·하천 등 산림 밖이므로 타지 않음으로 둔다 [가정] (북한산은 평균 고도 69 m 의 서울 시가지).
  임상도는 1:5,000 도엽(위도·경도 1.5′ = 약 2.8 km × 2.3 km) 단위라 산 하나에 20~25장이 필요하다. 받지 않은 도엽 자리는 [임시] 규칙을 그대로 쓴다.
  도엽 번호(8자리) = 위도 정수 2자리 + 경도 끝자리 + 1:50,000 도엽(15′, 4×4) 2자리 + 1:5,000 도엽(1.5′, 10×10) 3자리. 받은 도엽 5장의 실제 범위로 계산식을 확인했다.
- **반영 전 [임시]**: 남향(125~235°) 침엽수, 북향(290~70°) 활엽수, 그 사이 혼효림, 주변 600 m 평균보다 25 m 높은 능선 침엽수·낮은 계곡 활엽수, 경사 40° 이상 바위, 지도 하위 12% 고도의 평지(4° 미만) 초지 [모두 가정].
  "남향 소나무·북향 활엽수" 경향은 일반적으로 알려진 정성적 사실이지만 실제 분포와는 다르다.

### 14-3. 등산로 그래프
1. 선을 반 칸 간격으로 따라가며 지나는 칸 목록으로 바꾼다. 지도 밖으로 나가면 끊고, 끊긴 끝을 표시한다.
2. 노드 = 선의 끝 + 둘 이상의 선이 지나는 칸 + 지점(spot) 자료를 붙인 칸. 붙어 있는 노드 칸은 하나로 묶는다.
3. 노드 칸에서 선을 잘라 간선을 만들고, 같은 두 노드를 잇는 간선은 짧은 것만 남긴다.
4. 이름 없는 "그냥 이어지는 점"(간선 2개)은 없애고 두 간선을 잇는다.
5. 경유점은 더글러스-포이커 단순화(허용 1칸)로 줄이고, 64개(엔진 한도)를 넘으면 고르게 뽑는다.
6. 노드 종류: 지점 종류(MANAGE_SP2)로 판단 — 대피소·산장 → 대피소, 주차장·탐방지원센터 → 주차장, 정상 → 정상, 분기점 → 갈림길,
   시종점 → 막다른 끝이면 들머리(주차장), 아니면 갈림길. 가로등·벤치·계단·안내판 등 다른 지점은 쓰지 않는다.
   지점은 등산로에서 150 m 안에 있을 때만 붙인다 [가정].
   지도 경계에서 끊긴 끝 → 주차장(대피 목적지) [가정: 9 km 밖은 산불 영향 밖], 막다른 끝 중 낮은 곳 → 들머리(주차장) [가정].
7. 등산객 5팀은 정상과 높은 지점에 서로 1 km 이상 떨어지게 배치 [가정]. 놓을 곳이 2곳보다 적으면 등산로의 가장 높은 칸(기존 노드와 450 m 이상 떨어진 곳)을 노드로 추가한다.

시험: 실제 산림청 형식(EPSG:5186, cp949, 같은 필드 이름)으로 만든 가짜 SHP(`tools/make_test_shp.py`)로 변환 → 엔진 실행까지 자동 테스트한다.
