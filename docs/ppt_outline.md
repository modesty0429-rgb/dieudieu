### 6. 산불 확산은 이렇게 계산한다 [PC · 휴대폰 공통]
- 공식(크게): **확산 속도 R = 기본 속도 × 수분 감쇠 × (1 + 바람 효과 + 경사 효과)**
  - Rothermel(1972) 산불 확산 모델을 단순화했다.
- 요소 4칸 (각각 한 줄)
  - **숲 종류**: 임상도의 침엽수·활엽수·초지 등마다 기본 속도가 다르다. 바위·물·도로는 타지 않는다.
  - **수분**: 기온·습도로 연료 수분을 매분 계산한다. 습할수록 느려지고, 남향 사면은 더 건조하다.
  - **바람**: 바람이 불어 가는 쪽으로 크게 빨라지고, 맞바람 쪽은 느려진다.
  - **경사**: 오르막은 빨라지고(경사² 비례), 내리막은 최대 절반까지 느려진다.
- 번지는 방식 (그림 1개)
  - 30 m 칸마다 8방향으로 "속도 × 1분"만큼 불을 밀어낸다. 밀어낸 거리가 이웃 칸까지 닿으면 불이 붙는다.
  - 바람이 세면 불티가 날아가 떨어진 곳에서 새 불이 난다(비화).
- 결과 예: 같은 북한산 불이 습한 여름에는 6.8 ha, 건조한 겨울에는 46.1 ha를 태운다.
- 발표 노트: 계수와 가정은 말로만 설명한다. 슬라이드에는 넣지 않는다.

### 7. [PC] 실행 화면과 사용법
- 사용 순서: 산 고르기 → 지도에서 발화 지점 클릭 → 기상(직접·계절·예보·과거 관측) → 낮/밤 시각 → 등산객 팀 → 실행 → 재생 → ↺ 초기화
- C 엔진이 10시간을 1분 단위로 계산하고, 화면은 그 결과를 지도 애니메이션으로 재생한다.

### 8. [PC] 진화 전략과 헬기 살수 계획
- 4가지를 같은 화면에서 나란히 재생한다: 대응 없음, 방화선, 헬기, 둘 다
- 헬기 살수 계획표의 열: 출동 차수, 헬기 번호, 시각, 위도·경도, "백운대에서 남서쪽 1.2 km" 같은 위치, 목적
  - CSV로 저장해 바로 현장에 줄 수 있다.
- 위치는 불길 가장자리 중 "불이 가면 피해가 가장 커지는 곳"으로, 헬기끼리 겹치지 않게 고른다.

### 9. [휴대폰] 인터넷 없이 대피 안내
- 흐름: 산 선택(지도 미리 저장) → GPS 내 위치 → 불 정보 받기(QR·링크·문자, 또는 지도에서 직접 표시) → 대피로 계산 → "오른쪽으로 120°, 1.2 km" → 경보 알림 → 입구 도착 시 "대피 완료"
- 비행기 모드에서도 동작한다. GPS는 데이터 없이도 된다.

### 10. 실행 결과 (봄 건조한 날, 10시간)
- 막대그래프: 6개 산의 피해 면적(ha), 대응 없음과 방화선+헬기 비교

| 산 | 대응 없음 | 방화선 + 헬기 |
|---|---:|---:|
| 북한산 | 34.7 | 0.5 |
| 설악산 | 158.1 | 1.1 |
| 오대산(금산) | 115.8 | 0.4 |
| 지리산 | 148.9 | 0.5 |
| 팔공산(장수) | 35.7 | 1.7 |
| 한라산 | 530.6 | 430.5 |

- 숫자 3개
  - 5개 산은 피해가 **98% 이상** 줄었다. 초원이 넓은 한라산은 19%만 줄었다 → **큰 불에서는 대피가 먼저**
  - **등산객 전원 하산**: 6개 산, 2~5팀(15~21명)
  - 같은 조건을 100번 반복하면 피해가 11.4~163.3 ha로 **최대 14배** 차이 난다 → 한 번의 예측만 믿으면 위험하다
- 발표 노트용: 밤에는 헬기가 뜨지 못해 피해가 0.9 ha에서 8.6 ha로 늘어난다. 10시간 계산은 0.4초 걸린다.

### 12. 타 프로그램과의 차별점
- **차별점 4가지**
  - **같은 C 엔진을 휴대폰까지**: 서버 없이 휴대폰 혼자 계산한다. 결과는 PC와 9만 칸 모두 같다(테스트로 확인).
  - **실제 데이터**: 실제 산 6곳의 지형·숲·등산로와 기상청 예보·관측을 쓴다.
  - **예측에서 행동까지 한 흐름**: 확산 예측 → 대피로 → 진압 전략과 헬기 계획
  - **현실 조건 반영**: 계절·낮밤·눈, 100회 반복으로 본 불확실성
- **장점**: 빠르다(10시간 계산 0.4초). 인터넷 없이 동작한다. 화면을 바꿔도 엔진은 그대로 쓴다.
- **단점**: 실시간 불 위치는 관공서가 입력해야 한다. 계수 일부는 가정값이다.
- 선배 사례는 언급하지 않는다.

### 13. 5.1 사용한 프롬프트
- 단계별 프롬프트 13개(`docs/prompts/`)
  - 00 전체 지침, 01~07 엔진·GUI 단계, 08 낮밤, 08 실제 산, 09 사계절, 10 등산객 팀, 11 휴대폰 앱
- 예시 1개를 짧게 인용한다. 예: "대피 목표를 산 아래 안전한 곳으로 바꾸고, 대피하는 길도 안전해야 한다"
- AI가 틀린 것을 사람이 잡은 예 2개
  - 겨울에 눈 덮인 곳에서 불이 시작돼 시뮬레이션이 실패했다 → 산마다 눈 높이를 정하고, 발화 지점을 숲으로 자동 이동
  - 제주 임상도 도엽 번호가 틀렸다 → 실제 파일과 대조해 고쳤다
- 매 변경마다 자동 테스트를 돌리고 변경 기록을 남겼다.

### 15. 5.3 본인 작성 코드
- GitHub 프로젝트 코드는 가져다 쓰지 않았다. 계산·화면 코드는 모두 우리 저장소에서 AI와 함께 작성했다.
  - 외부에서 가져온 것은 위의 라이브러리와 공개 데이터뿐이다.
- 확산 공식(Rothermel)과 연료 수분 식(Simard)은 논문의 식을 C로 직접 구현했다.
- 줄 수 표: C 9,982 / Python 9,420 / JavaScript 1,530
- 커밋 61개 (main 기준, 2026-11-26)

### 16. 6.1 전체 구조 (블록도)
```
기상청 API ─┐
지형·임상도·등산로 ─┼→ PC 화면 (Python) ─ 시나리오 ini → C 엔진 (c_core) ─ 결과 csv/json → PC 화면
                      └─ QR·링크 → 휴대폰 앱 (JavaScript) ↔ 휴대폰 안의 C 엔진 (WebAssembly, 같은 코드)
```

### 19. 6.4 main() 동작 (순서도)
`main()` → 명령줄 해석 → `load_scenario()`(지형·숲·등산로·등산객) → 모드 선택
→ [1분마다 600번: 날씨 갱신 → 불 번짐 → 경보 판단 → 대피 이동 → 진화 적용]
→ 진화 전략 비교 → 100회 반복 → 결과 파일 쓰기 → 메모리 해제
